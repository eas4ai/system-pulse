# Intel Linux sources and capabilities

Recorded 2026-09-06. Implementation is in [the Intel adapter](../../../examples/system_pulse/collectors/src/intel/mod.rs), invoked by the existing `HostCollector` worker. Intel hardware accuracy is **unverified**. Fixture tests and the AMD development host do not establish native Intel support.

## Boundary, freshness and resource contract

The only new dependency is Linux-target `libc`, already present in the workspace lock, for read-only `ioctl` and `perf_event_open`. No vendor runtime, Sysman, production CLI, extra thread or polling service was added. Native files use owned `File` handles. DRM opens are read-only/nonblocking and verify the opened character device number against the same physical sysfs node.

The two-call query boundary caps allocations at 1 MiB, validates both ioctl return values, i915 per-item negative status, and unchanged returned length. Decoders read native-endian integers from checked byte slices; they never cast byte buffers into structs. Counts are bounded at 512; exact record sizes, reserved fields, duplicate identities, local sizes and engine selectors are checked. GT IDs come from engine records or sysfs names, never array position. No shader-topology estimate becomes activity.

Perf group reads check count, exact length, enabled time and running time. A first observation, reset, zero/regressed time, failed read, changed configuration, multiplexed interval, or impossible activity produces a non-current result. No scaling estimate or clamp conceals the failure. Original active/total, enabled/running time, PMU configurations, capacity, unit denominator, query start/end and both observations remain available to recompute values. The monitor summary names one actual engine sensor; it does not aggregate engines into whole-device load.

Sysfs values are limited to 4096 bytes; each scanned directory, per-device remembered field set and physical inventory is bounded at 512. PMU handles and baselines follow stable sensor identities; failed reads close handles and retry on the next collection. Physical disappearance prunes inventory, fields and counter state. Known card associations are checked before frequency reads so a reused alias cannot transfer measurements to another device.

SPEC-review corrections additionally require fresh unique hwmon provider/channel discovery before reading any remembered hwmon field. Replacement, failed provider identity (including an unreadable peer) or ambiguity invalidates the old attribution and energy baseline; recovery warms up. A renamed hwmon ordinal keeps the physical provider/channel sensor identity.

Each i915 event validates its own metadata. A malformed or denied event publishes its own failed/unavailable reading while valid peer engines continue. Previously known event paths retain their engine identity on metadata failure, close their handle and clear their baseline. A never-readable configuration is identified by the exposed event name without inventing its engine class.

CPU-visible local-memory used/free operands must fit the corresponding whole-region operands before any derived allocation is published. Powercap scans recognize Intel RAPL zone selectors and skip ordinary attribute files; failed identities on actual package or child-zone candidates invalidate uniqueness with a path-qualified reason. An incomplete scan cannot select an arbitrary package or PP1 domain.

## Unverified or unavailable evidence

- Intel integrated and discrete native discovery, accuracy, suspend/resume and permission behavior remain unverified. Required GPU-008 host evidence is still pending.
- No i915 query capability bit proves reliable zero-free-difference accounting across old/restricted kernels. That ambiguous equality stays unavailable while dedicated total remains available.
- RAPL package/graphics-domain attribution on multiple dies/packages or unevidenced xe integrated hardware is not claimed. No API discovery omission is labeled unsupported.
- Unknown layouts/units are rejected; permission denial, absent interfaces and malformed responses retain distinct reasons and availability.
- CPU-visible local memory overlaps its parent VRAM region and is explicitly labeled as a subset. Neither is added to the other.

The C layouts and constants were independently checked with the fetched kernel UAPI headers on the x86-64 AMD development host: i915 item/query 24/16 bytes, xe query 40, memory region 88 for both drivers, engine record 56/32, and relevant offsets including perf VER0. Ioctl numbers were `c0106479` and `c0286440`. This verifies the host ABI layout, not Intel ioctl behavior. [UAPI license notices](../../../examples/system_pulse/collectors/src/intel/UAPI-NOTICE) accompany the translated layouts.
