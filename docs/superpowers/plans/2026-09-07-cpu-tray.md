# CPU Tray Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for the independent tray-fork task and review. The app runtime work stays with the primary agent.

**Goal:** One live combined CPU graph in the tray, with monitoring retained after closing the dashboard.

**Architecture:** The generic fork provides native tray lifetime and cached host availability. System Pulse owns the icon renderer and Open/Quit actions. WorkspaceView retains the single sampler and bounded history without requiring a native window; ApplicationView recreates window-dependent views on reopen.

**Tech Stack:** Rust, GPUI Kit 0.6.0, gpui-pre 0.3.2, gpui-tray fork, Linux StatusNotifierItem/DBusMenu.

### Task 1: Compatible tray fork

Files: sibling gpui-kit-tray Cargo.toml, README.md, src/tray.rs, src/backend/mod.rs, src/backend/linux.rs.

- [ ] Alias gpui to package gpui-pre =0.3.2 and gpui_platform to gpui-pre-platform =0.3.2, preserving the platform features. Remove the Zed git revision.
- [ ] Add Tray::is_available() using cached native availability. Linux tracks successful registration and a registered host; macOS/Windows report an open native item. Never block from this getter.
- [ ] Make Linux watcher checking periodic even under continuous icon updates; handle host disappearance and return. Bound synchronous D-Bus method waits.
- [ ] Verify fork tests, example build and strict lint. Commit locally for review before publication.

### Task 2: Retain monitoring across native windows

Files: src/workspace.rs, src/screens.rs, new src/workspace/window_lifetime.rs.

- [ ] Add an optional attached window handle to WorkspaceView. Move its timer to the application executor and dispatch collection with or without a Window.
- [ ] Extract optional-window snapshot acceptance: update readings/history/catalog/diagnostics in both states; reconcile native dock geometry only while attached.
- [ ] On close, record preferences and detach the window. On reopen, build fresh DockArea and ScreenView entities against the retained workspace, reapply appearance, and refresh the current snapshot without duplicating history.
- [ ] Verify with a GPUI test that detached samples advance bounded history and that reopening preserves the active tab, selected device and single service.

### Task 3: CPU tray and application lifetime

Files: new src/tray.rs, src/tray/icon.rs, src/main.rs, src/lib.rs, Cargo.toml and Cargo.lock.

- [ ] Render a 32px RGBA icon from the existing aggregate CPU series, fixed 0–100% vertical range. Use current CPU color, a readable dark plot, and gaps/status for missing or stale samples. Test zero, full, nonfinite, missing, bounded time history and tooltip values.
- [ ] Retain the tray and ApplicationView at app scope. Publish icon changes only when CPU history/status changes. Add native activation and Open System Pulse/Quit actions.
- [ ] Close keeps monitoring only when a tray host is available. Reopen an already-open window by raising it. Restore a closed window if host availability disappears. Keep normal close-to-exit on unsupported desktops.
- [ ] Quit uses existing final persistence and deterministic tray cleanup; no extra collector is introduced.

### Task 4: Native verification and delivery

Files: scripts/system-pulse/tray_replay.py, relevant regression tests, docs/user-guide.md and package/README.md.

- [ ] Run unit/lint/format checks, then native SNI protocol tests in an owned private X11/DBus session. Verify graph bytes change with accepted CPU history, native activation, close/reopen with increasing sequence/history, unchanged preferences, host loss/recovery and menu Quit with persistence.
- [ ] Verify absent-host launch and ordinary close. Existing native acceptance must retain its close-to-exit behavior in sessions without a host.
- [ ] Review spec compliance and code quality. Publish the fork commit, pin it in the app, run a locked optimized build and verify the exact installed executable. Keep the user's running process and configuration untouched.
